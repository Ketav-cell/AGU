# GridSpark AI

**Open-data wildfire ignition risk prototype — Lane County, Oregon**

> **Decision-support framing:** GridSpark AI is a decision-support tool for
> transmission-corridor inspection prioritization, vegetation management
> prioritization, and risk screening. It does **not** automate infrastructure
> shutoffs, issue operational recommendations, or replace utility engineering
> judgment. All outputs are research prototypes intended for academic
> presentation and further validation.

---

## Why this project

Wildfire risk near electrical infrastructure has traditionally required
proprietary data and expensive licensed models. GridSpark AI tests whether
freely available open datasets — HIFLD, FPA-FOD, MTBS, Sentinel-2, and NOAA
ISD — are jointly sufficient to build a reproducible ignition-risk screening
model at the county level.

The Holiday Farm Fire (Lane County, OR, September 7 2020) is the prototype
validation event. This fire burned approximately 173,000 acres along the
McKenzie River corridor and is well-documented in public records, making it
an ideal open-data feasibility case.

This work supports the open-data democratization of wildfire risk science —
enabling smaller utilities, county emergency managers, and community planning
bodies to access reproducible risk insights without proprietary tools.

## Quick start

### 1. Install dependencies

```bash
cd gridspark-ai
pip install -r requirements.txt
```

### 2. Run the automatic scripts (no credentials needed)

```bash
# Initialize feasibility matrix
python scripts/build_feasibility_matrix.py

# Generate AOI GeoJSON (1/3/5 km buffers around ignition)
python scripts/generate_aoi.py

# Verify HIFLD transmission lines (queries public ArcGIS REST)
python scripts/verify_hifld.py

# Attempt NOAA ISD download
python scripts/verify_noaa_isd.py

# Create training table schema
python scripts/build_training_table_schema.py
```

### 3. Complete manual downloads (see next section)

### 4. Run remaining verification scripts

```bash
python scripts/verify_fire_labels.py
python scripts/verify_fire_perimeter.py
```

### 5. Open notebooks

```bash
jupyter notebook notebooks/01_feasibility_matrix.ipynb
```

## Data layers

| Layer | Source | Purpose | Spatial resolution |
|---|---|---|---|
| HIFLD Electric Transmission Lines | DHS/HIFLD | Corridor identification | Vector (line) |
| FPA-FOD Wildfire Occurrence | USDA FS | Ignition labels (approximate) | Point (±km uncertainty) |
| MTBS/WFIGS Fire Perimeter | USDA/USDI | Burn boundary validation | Vector (polygon) |
| Sentinel-2 SR Harmonized | ESA / GEE | NDVI, NDMI, NBR features | 10–20 m raster |
| NOAA ISD Hourly Weather | NOAA NCEI | Fire-weather features | Station point |

### Important data constraints

**HIFLD:** Transmission lines represent 138 kV+ bulk-power infrastructure operated
by transmission owners. They are not local distribution poles or service
conductors. Pole-level risk modeling requires separate distribution system
data (e.g., PG&E, PacifiCorp open datasets, or utility PSPS filings).

**FPA-FOD:** Ignition coordinates are not GPS-verified exact points. They are
reported locations from agency records that may differ from true ignition by
hundreds of meters to several kilometers. Buffer sensitivity tests at 1 km,
3 km, and 5 km are required.

**Sentinel-2 band resolution:** B11 and B12 (used in NDMI and NBR) are 20 m native
resolution. B8 (NIR, used in all three indices) is 10 m. Indices derived from
mixed-resolution bands are reported as "10–20 m Sentinel-2 indices."

## Feasibility matrix

The five-layer feasibility matrix is the go/no-go gate before model training.
After running all scripts:

```bash
cat outputs/feasibility_matrix.md
```

All five layers must show **Pass** before proceeding to Notebook 03 model
training. If any layer is **Manual Check**, complete the corresponding
manual download and re-run the verification script.

## Scientific limitations

1. **Single-county prototype.** Results from Lane County, OR may not generalize
   to other utility territories or geographic contexts without revalidation.

2. **Transmission vs. distribution.** This prototype uses HIFLD transmission
   infrastructure. Most wildfire-igniting faults in historical records involve
   distribution-level poles and conductors, which require different data sources.

3. **Spatial leakage risk.** If model evaluation uses random pixel splits, test
   performance will be inflated due to spatial autocorrelation. Use event-out
   or county-out cross-validation (Notebook 03).

4. **Label uncertainty.** FPA-FOD labels an ignition as "utility-related" only
   when cause codes indicate electrical equipment. Cause attribution in ICS-209
   and FPA-FOD records carries its own uncertainty.

5. **Weather station distance.** Eugene Airport is ~56 km from the Holiday Farm
   ignition point in the Cascade foothills. Local terrain-driven wind conditions
   at the ignition site may differ significantly from station observations.
   ERA5 reanalysis (0.25° grid) can supplement station data.

6. **Pre-train feasibility gate.** Do not train a final ML model until the
   feasibility matrix passes. Do not report model AUC from prototype outputs
   as operational performance estimates.

## AGU presentation guidance

This prototype is designed for presentation at the American Geophysical Union
annual meeting under themes of open-data science, wildfire risk, and
infrastructure resilience. Recommended framing:

- "Feasibility study" or "open-data pipeline prototype"
- "Inspection prioritization tool" — not "ignition prediction system"
- "Decision support for vegetation management" — not "shutoff map"
- "Risk screening layer" — not "risk score for operational use"

Do not cite FPA-FOD coordinate precision or model accuracy without explicit
uncertainty quantification.
